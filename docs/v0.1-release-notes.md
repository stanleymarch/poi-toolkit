## Обновление PBF

PBF скачивается с Geofabrik:

```bash
curl -sL -o input/pfo.osm.pbf \
  "https://download.geofabrik.de/russia/volga-fed-district-latest.osm.pbf"
```

Извлечение OSM (где установлен `osmium-tool`):

```bash
osmium extract -b 42,51,60.5,62.5 input/pfo.osm.pbf -o bounded.osm.pbf
osmium tags-filter bounded.osm.pbf \
  nwr/historic nwr/tourism nwr/amenity=museum nwr/amenity=place_of_worship \
  nwr/leisure=park nwr/leisure=nature_reserve nwr/natural=water \
  nwr/natural=waterfall nwr/natural=spring nwr/natural=beach \
  nwr/water=lake nwr/water=pond nwr/water=reservoir nwr/geological \
  n/natural=peak n/natural=cave_entrance n/natural=spring n/natural=cliff \
  n/natural=rock n/natural=stone n/natural=tree \
  -o filtered.osm.pbf
osmium export filtered.osm.pbf -f geojsonseq --add-unique-id=type_id \
  -o osm.geojsonseq
```

> Замечание по атрибуции данных: run `pfo-v0.1` был собран до появления
> immutable collection provenance, поэтому его
> `reports/collection-provenance.json` пуст. Контракт v1 требует непустой
> provenance; для этого сформирован восстановленный v1-экспорт
> `workspace/pfo/pfo-v0.1-v1/` (команда `recover-release`, см.
> `docs/ARCHITECTURE.ru.md` §11.5): provenance реконструирована из
> неизменяемых сохранённых входных данных (raw-снапшоты, territory JSON,
> source manifest-ы, PBF) и явно помечена полем `recovered`. Это отдельный
> исторический v1 bundle; его consumer-side acceptance зафиксирована в
> [release evidence Nearventure](https://github.com/stanleymarch/nearventure/blob/main/docs/release-evidence/beta-0.1-acceptance.md).
> Для следующих релизов provenance обязательна на этапе `collect`; каждый
> новый bundle проходит собственные checksums, compatibility и acceptance.

## Handoff и consumer acceptance

Этот репозиторий производит v1 bundle, но не выполняет deployment. `export-sql`
формирует data-only SQL + строгий import manifest; producer передаёт неизменяемые
байты и их идентификаторы/digests. Nearventure владеет trusted root, dry-run,
import, audit и rollback. Полная граница: [docs/nearventure-handoff.md](nearventure-handoff.md); каноническая consumer-процедура:
[Nearventure data refresh](https://github.com/stanleymarch/nearventure/blob/main/docs/data-refresh.md).

Для legacy run `pfo-v0.1` отдельный v1 bundle находится в
`workspace/pfo/pfo-v0.1-v1/`; его provenance реконструирована и помечена
`recovered`. Его датированная acceptance/import evidence не превращает исходный
`pfo-v0.1` или будущий bundle в автоматически accepted release.

Ранние инструкции (прямые `psql -f`, ручные `ALTER TABLE ... RENAME`
staging-swap/rollback, `scripts/atomic-deploy.sh`) **отозваны**: producer не
запускает SQL, importer или consumer deployment. `scripts/atomic-deploy.sh`
сохранён только как permanently disabled compatibility stub: он завершится с
ненулевым кодом до чтения, копирования или удаления артефактов и не имеет доступа
к БД. Единственный разрешённый путь импорта в БД — manifest-валидируемый handoff
Nearventure.
