## Реализовано в текущем исходном коде (проверено тестами)

### OSM Address Index

Локальный индекс адресов OSM-зданий, проверяемый **до** обращения к Photon
(`pnpm cli build-address-index`, затем автоматически внутри `geocode`).
Механика описана в `docs/ARCHITECTURE.ru.md` (раздел 5.6). Конкретные
счётчики (сколько записей получили геометрию из индекса) фиксируются в
отчётах конкретного run и не заявлены здесь как постоянная метрика.

### Resolver Gates

| Gate | Суть |
|---|---|
| exact-ID validation | `ref:knid`, `heritage:ref`, `wikidata` — не безусловная истина; sanity-проверки расстояния/адреса |
| MKRF tightening | Музей Минкультуры сближается с OSM по proximity (≤60 м, mutual-nearest) |
| generic-name block | Generic-имена не участвуют в fuzzy-сближении |

### Semantic Hardening

| Gate | Описание |
|---|---|
| `museumCategoryMismatch` | Блокирует релиз, если entity-музей не совпадает с источником |
| `specificNearDuplicates` | Две entity одной категории и имени на **≤30 м** (хотя бы одна с OSM-источником) |
| `registryMuseumWithoutPhoto` | Музей из реестра без фото |
| `standaloneWikivoyageNature` | Природа только из Wikivoyage (без OSM) |

### Прочее

- **Museum-by-name**: OSM `tourism=gallery` с именем «музей» → `MUSEUM` facet
- **Generic spring noise**: «Родник» без `ref`/`wikidata`/`heritage` →
  `unanchored_generic`
- **OSM area↔way identity**: детерминированная связь `a<2×ID>` = `w<ID/2>`
- **`nearDuplicatePairs`**: массив пар в hardening-отчёте (для отладки)
- **Preflight**: `pnpm cli preflight` проверяет Node ≥22, территорию/PBF,
  osmium-tool, Photon, `MKRF_API_KEY` (точный набор — в ARCHITECTURE.ru.md)
- **Экспорт v1**: `export-sql` эмитит data-only SQL + строгий import manifest
  (контракт Nearventure importer)

## Исторические планы v0.2 (не обязательства для будущего acceptance)

- P2.1: pipeline progress bar и метрики
- P2.2: автоматическая верификация целостности артефактов run-а
- P2.3: coverage diff gate (сравнение с предыдущим релизом)
- P2.4: JOSM review bundle (GeoJSON → `.osm` для полевых проверок)
- P2.5: историческая задача importer acceptance по контракту manifest v1
  (staging, checksum, restricted-SQL грамматика, rollback/no partial write).
  Она принадлежит Nearventure; датированные результаты приведены в
  [consumer release evidence](https://github.com/stanleymarch/nearventure/blob/main/docs/release-evidence/beta-0.1-acceptance.md),
  а не в этом плане.
- P2.6: point-on-surface координаты для полигонов в экспорте
- P2.7: historical consumer-adoption task (карта/маршруты/каталог), а не
  прямая интеграция toolkit→Mini App. Будущий producer bundle передаётся только
  через immutable trusted-root handoff.
- P2.8: автоматическое обновление PBF по расписанию
- P2.9: заполнение collection provenance (дата/checksum PBF, source manifests)
  как обязательное требование manifest v1
